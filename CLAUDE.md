# AgentReplay — agent guide

Local CLI that turns Claude Code session JSONL into a single self-contained HTML **replay** of how the agent worked — what it explored, how its plan changed, what it edited, where it got stuck, what finally worked. MIT, fully local, no backend. Session format in `docs/session-jsonl-format.md`.

## Commands

```sh
pnpm install
pnpm build          # core → viewer (static export + inline) → cli
pnpm test           # Vitest — parser + heuristics in packages/core
pnpm typecheck
pnpm dev:viewer     # viewer hot-reload against packages/viewer/lib/sample.json
                    # regenerate it after any core model change:
                    # node packages/cli/dist/index.js --demo --no-ollama --json > packages/viewer/lib/sample.json
pnpm cli -- --demo --json   # run the CLI in dev
```

Node ≥ 20, pnpm ≥ 9, TypeScript strict everywhere.

## Layout and dependency direction

- `packages/core` — parser + heuristics. **No UI or CLI deps, depends on nothing internal.** Public API: `analyzeSession(path)` in `src/index.ts`.
- `packages/viewer` — Next.js 14 App Router, `output: 'export'` only (no SSR, no API routes). `scripts/inline.mjs` post-build inlines everything into one HTML file, written to `packages/cli/assets/viewer.html`.
- `packages/cli` — commander + inquirer. Injects `JSON.stringify(analyzedSession)` into the viewer HTML at runtime. Never imports viewer code, only the built asset.

## Type contract

`packages/core/src/types.ts` is the single source of truth for the data model — read it before touching core or viewer. **All timestamps are ISO 8601 strings (`Iso`), never `Date` objects**: the `AnalyzedSession` is JSON.stringify'd straight into the generated HTML, so in-memory shape must equal wire shape. Do not introduce Dates, Maps, or anything that doesn't survive JSON round-tripping.

## Heuristics

Pure functions in `packages/core/src` (`phases.ts`, `loops.ts`, `files.ts`, `diffs.ts`, `concepts.ts`, `plans.ts`, `trail.ts`, `verify.ts`, `title.ts`, `checks.ts`, `timeline.ts`, `commands.ts`, `summary.ts`), each with Vitest tests against fixtures in `packages/core/test/fixtures/`.

Rules learned from real sessions, all load-bearing: **a declined tool call is `outcome: 'unknown'`, never an error** (rejected permission prompts were being counted as stuck runs); **phase boundaries never split a debugging episode** (`mergeAcrossDebugRuns` in `phases.ts` — adjacent phases only, ≤10min between attempts, or the breakthrough ends up in a different phase from its stall); **debug stats count loops by turn range, not by which sequence they were filed under**; **reading is reading whatever tool carried it** (`rg`/`sed -n`/`cat`/`git log` are exploration — see `shellKind` in `checks.ts`); **phases cut at work seams**, not only at user turns (plan exit, 10-minute silences), or one assistant turn swallows the session; **only check commands decide pass/fail** (`rg` exiting 1 means no matches); **`.claude/**` is the harness's, not the developer's** (`isHarnessPath`); **durations are active time** (`Phase.activeMs`), since sessions span whole days with hours of idle. Deterministic, no I/O. Degrade to empty results, never throw. Parser rule: schema drifts between Claude Code versions — skip and count bad lines, keep `raw` on every event, never crash.

The narrative layer (`narrative.ts`, `buildBrief`) is deliberately thin: a session title (`title.ts`), header stats, **at most one** headline sentence — and only when there is a real finding — plus 2–4 ranked takeaways (each with a hard data bar; no generic advice) and a head per phase section. Each head carries an `intent`: the ask behind that phase, **quoted from the session** (a plan quotes its own objective sentence). Quoting the transcript is not narration — but never generate that line. There are no phase stories: structure carries the meaning, so if a view needs a paragraph to explain itself, fix the view. Cross-session facts arrive pre-computed via `BriefExtras`.

`analyzeParsedSession(session)` in `index.ts` is the one composition of every heuristic — the CLI and the tests both go through it, so a new view can't drift out of a hand-built fixture.

**Detection is not presentation** (`replay.ts`, `selectReplayEvents`). `analyzed.events` keeps every checkable moment; `analyzed.replay` is the small ordered set the graph draws — the shortest truthful story, optimized for non-redundancy, causal importance, arc coverage and outcome relevance, all deterministic. The stages, in order: **demote** (of several ROOT CAUSE candidates the last stated is the conclusion; earlier ones present as discoveries — the arc the session walked), **dedup** (a later finding in the same phase, weaker or equal kind, whose anchors are all already in an earlier finding's evidence and which adds none, is a restatement; earlier-only and same-phase-only, so a causal step toward the root cause and a cross-phase callback both survive), **drop stubs** (`plan drafted — N steps` never stands beside a spoken decision; a mid-session `Tests passed` never stands beside a terminal verification — failures are exempt, a failure is what happened, not a status), **merge runs** (consecutive implementations with nothing but implementations between them are one beat, `N files changed`; same for passing checks; any key/outcome event in between means direction changed and the beats stay separate), **score** (weight + repetition + forward reuse — a later event `relatesTo` this turn or reuses its anchors — + causal position before the phase's conclusion, − a penalty for findings after the outcome), **cap failures per phase** (several distinct failures in one phase are one struggle: keep the strongest, unless a failure precedes a kept finding — the transition is the story), **pick** (must-keep: outcomes, the root cause, pivots, quoted decisions — never cut; the largest implementation run per phase, ≤2; the rest by score with phase-coverage tiebreak against a soft budget — 5/7/9 by working time — that should almost never be the reason an event disappears; a score ≤1 is noise regardless of room). Ollama never touches any of this: it must not decide what happened, what is a root cause, what is a duplicate, or what enters the replay.

**Everything the viewer draws is computed in core and serialized** — trails (`trail.ts`), plan-step diffs (`plans.ts`), debug chain fields (`loops.ts`), verify results (`verify.ts`), the ribbon's axis (`timeline.ts`), grouped command actions (`commands.ts`). `AnalyzedSession.trails` / `.verifications` carry per-phase views. Never push a heuristic into a component; the viewer imports types only, never core's runtime (that would pull `node:fs` into the bundle and break the static export).

Ollama (`ollama.ts`) does exactly four things — concept relabeling, session-title polish, **tightening a section summary the session already contains**, and takeaway fluency rewrites — and must never do more. It may compress a sentence the transcript already holds; it may never author one, and it never touches a `derived` summary (that sentence is ours, not Claude's). It may never add facts: rewrites that introduce numbers absent from the heuristic input are discarded, a polished title that uses a significant word absent from the user's own request is rejected, and takeaway snippets are never touched. 1s probe, 30s budget shared across all calls, heuristic fallback on any failure; it remains fully optional.

## The viewer (one layout)

The page is four things and nothing else: **header** (title, stats, the ask, headline), **ribbon** (the map — phases on a working-time axis with its key; hovering a block lights its chapter in the graph), **event graph** (the story — one chronological column of ~8 moments, `EventGraph.tsx`, phases as quiet chapter markers with the connector breaking between them), **evidence drawer** (the proof — `EvidenceDrawer.tsx`, a fixed non-modal right panel: exact snippet with quotes, speaker · time, files, the full turn markdown-rendered via `Markdown.tsx`, tool activity). **Evidence never opens inline** — inline expansion pushed every later event down and destroyed the replay's spatial stability; selecting an event must never move the events below it. The graph itself carries no quotation marks and no speaker labels: the wording is still verbatim, but the graph is a reconstruction from evidence, and provenance belongs in the drawer. There is deliberately no second answer to "what happened": the phase sections, left spine, root-cause card, pivot rows and outcomes block were four more answers on one page, and were deleted when the graph shipped. Core still computes and serializes `brief.sections`, `trails`, `verifications`, `commands` and `takeaways`; the viewer currently draws none of them — future evidence-layer candidates, or dead weight to remove once the graph's evidence view settles.

The graph draws `analyzed.replay` verbatim — selection lives in core (`replay.ts`, tested against fixtures), and the viewer's only additions are the opening-request node (presentation of `brief.openingPrompt`) and the drawing itself. The drawer's full turn is collapsed behind `View full turn →`, giving three levels of compression that must stay distinct: **graph → evidence → transcript**. The `↑ first seen HH:MM` link is one of the few things a replay can show that a transcript cannot — an earlier finding feeding a later decision — and stays subtle and textual: never draw edges across the page.

## Design tokens (viewer)

Defined in `packages/viewer/app/globals.css`. Rules:

- Blue/amber/purple = tool category (read/write/bash). Green/red = outcome only. Cyan `--selection` = hover/focus/revisit only. Never mix axes.
- Colour lives on **small marks** — the graph's node marks and chips, the ribbon's blocks and ticks — never as a tint across a whole block.
- **`Evidence →` belongs to its event.** The affordance ends the node's metadata footer (`Article.authorId · Evidence →`), never floats at the far edge on a spacer — an affordance detached from its object reads as page chrome.
- **The structure must register before the words do.** The connector sits one step up the border scale and marks run 9.5–15.5px; someone squinting should see small beat / IMPORTANT BEAT / chapter break / outcome without reading a line. Still 1px, still quiet — presence comes from the marks, not brightness.
- **Three visual weights, not fifteen components**: `normal` (`○`, quiet), `key` (`◎ root cause`, `●` discovery, `◆` decision, `↻` goal changed, `✕` failure — bigger type, more air, a coloured chip), `outcome` (`⚠` blocked / `✓` verified — the tail). The chip carries the verb so the content can stay session-authored.
- **A panel marks an exceptional or actionable object, never ordinary session structure.** Today that is the evidence drawer. The rule is the sentence, not the count — if something new genuinely earns a panel, it may have one.
- **Selection brightens, never spotlights**: a selected node's mark and text go full primary and its affordance goes cyan; the rest of the graph is NOT dimmed, and there is no selected-card background — the story stays readable whole while the drawer is open.
- Radius ≤ 6px, no gradients/glows, animations ≤ 200ms, base font 14px (IBM Plex Sans; Plex Mono for paths/diffs/timestamps).
- **The scale has to have a top and a bottom.** Title 28 / summary 16 / headline 17 / quote 14.5 / body 14 / meta 11–12. Everything landing between 11 and 13px reads as one undifferentiated block with no entry point — density is not the same as flatness.
- **Chrome looks like a control; the editorial surface stays quiet.** In the drawer and topbar, buttons have borders and hover states. On the graph itself the affordance is small mono text (`Evidence →`) that brightens on hover, and the whole node body is clickable — bordered buttons repeated down the column made the story read as a dashboard, and the control must never compete with the event it belongs to.
- **A headline carries no fixed mark.** The ⚠ was hardcoded, so "Everything passed first try" arrived under a warning triangle. Tone comes from the span styles.
- File paths truncate from the left (keep filename, single `…`).
- No Tailwind, no chart libs, no force graphs, no markdown libs. Diagrams are hand-rolled inline SVG (the ribbon) or CSS (the graph's connector and marks) — they must survive being inlined into one offline file.
- The ribbon's axis is **working time** (`Timeline` in `timeline.ts`), not clock time; pauses become notches that still name their real duration. Never draw a session to the clock — most of a real one is idle.
- **Every colour in the band is named once, in the band.** The key is laid along the axis it explains, not boxed beside it: a kind is labelled at its widest block and nowhere else (`Debug` three times is one label), and a kind whose widest block is too narrow to sit under joins the group at the right rather than going unnamed. Labelling every block is what made an earlier ribbon collide on long sessions — the fix is one label per kind, not no labels. Placement is one left-to-right walk with a cursor against a reserved right-hand strip, so nothing can overlap; the swatch carries the colour and the name stays legible (a phase name set in its own colour makes `plan` grey-on-dark).
- **Semantic events are the primitives** (`events.ts`): question, hypothesis, discovery, rootCause, decision, pivot, implementation, failure, verification, blocker. Two sources only — quoted sentences and structural facts. **Never infer**; every event carries `turnIndex` + `evidence` so a claim can be checked, and a wrong one is visibly the session's, not ours.
- **Select, clip, group, rank and count are ours. Wording is the session's, wherever wording exists.** The constitution of the whole product, and the thing to check first in review: if a string in an event is not a clip of the transcript, a count, or a fixed label, it is a bug. `SessionEvent.label` is the scannable line — `text` with its pointer opener stripped (`The goal is clear:`, `There it is.`) and clipped to the first clause; every word in it is a word the session used, in that order. A structural event may compose from tool calls and arithmetic (`4 files changed (+27 −21)`), and stands aside when the turn said it in words.
- **An ellipsis is a bug, not a budget.** Every `…` seen in the wild was a span-selection failure, never a length one: the sentence fits once the parenthetical aside is dropped, or once the label starts at the clause the marker matched instead of at character zero. `labelOf` tries, in order — strip the lead-in, drop `(asides)`, take the matched clause and run forward while it fits, cut at the last clause boundary — and only then truncates. **Never reach for Ollama to shorten a label**: it is optional (most readers would still see the ellipsis), non-deterministic across runs, shares one 30s budget across every call, and a model-authored label breaks *wording is the session's* exactly where it matters most. Compressing a section summary stays its job; labels are not.
- Extraction is four stages in this order — **gather, collapse, rank, relate**. Ranking must see the grouped set (a failure repeated three times outranks one), relating must see the ranked set (only findings look back). Three ranks, not fifteen components: `normal` (ordinary step), `key` (a finding), `outcome` (blocker, or a final passing check).
- **A verdict is never a finding.** `All green: 84 tests, no type errors, no lint findings` satisfies the root-cause marker that exists for `no author tag, no result`; findings are rejected in a verify phase and against `VERDICT`, or the loudest node on the page is a check report.
- **`relatesTo` is the most useful thing a replay carries and belongs to neither event** — the file noted in Explore that turns out to be the root cause in Debug. Strict on purpose: earlier phase only, findings only, and the shared evidence must be a path or a dotted symbol (two phases that both ran `Tests` both ran tests; that is not a thread coming back).
- **Findings outrank bookkeeping.** Key moments get the type and the air; implementations are connective tissue (≤2 nodes); the graph ends on the outcome, never on a step. Phases are quiet group headings — a reader should remember `authorId was the root cause`, not `there was an Explore phase`.
- **Claim first, proof one click deeper.** A node is chip + the session's clipped words + a thin support line; speaker attribution, the full sentence, files and the raw turn live in the evidence expansion. If Claude concluded something wrong, the replay shows what was concluded, never presents it as an analysis result.
- **Group repeats everywhere** — the same failure three times is one node with `×3`, never three nodes.
- Show **actions and results, never command lines** — a structural node says `4 files changed (+27 −21)` or quotes the line that explains the outcome; when there isn't one, say `typecheck failed` and stop.
- When in doubt: denser, quieter, smaller radius.

## Ethos and scope

- Prefer boring code: clarity over cleverness, no premature abstraction, delete dead code. Strangers read this repo.
- Out of scope (do not build): web app/hosted version, upload, shareable URLs, accounts, cloud API keys, in-browser models, local HTTP server, light mode, mobile, multi-session dashboards, Cursor/Codex support, watch mode.
- **Never add telemetry or analytics of any kind. Permanent rule.** The only permitted network call in the entire product is to localhost Ollama, and it must remain optional.
